# Pre-registration — monomer-level readout on the flat graph (M1)

Written **12 August 2026, before any job is submitted.** Nothing below may be edited after the
first result lands. Corrections go in a dated addendum at the bottom.

---

## 1. Question

Does having an explicit monomer-level representation, with inter-monomer information still
flowing at the atom level, account for the wD-MPNN → HPG-hier gap?

M1 isolates one architectural choice: whether the polymer vector is formed by pooling atoms
directly to the polymer (wD-MPNN) or by first pooling atoms to monomer vectors and then
combining the two monomers with their mole fractions (M1).  Everything else — the flat graph
containing both monomers, the stochastic inter-monomer edges, the weighted message passing,
the edge weights, the atom features — is identical to wD-MPNN.

## 2. Mechanism, stated precisely

The readout is changed from `WeightedMeanAggregation` to `MonomerLevelStoichAggregation`:

```text
for each polymer p:
    h_A = mean of atom embeddings where monomer_index == 0
    h_B = mean of atom embeddings where monomer_index == 1
    g_p = f_A * h_A + f_B * h_B
```

`f_A` and `f_B` are the per-atom mole fractions already stored in `atom_weights`.  The
within-monomer mean is unweighted; stoichiometry is applied once at the monomer level.

To make this possible, a genuine `monomer_index` array (shape `[num_atoms]`, values 0 or 1) is
plumbed through `PolymerMolGraph`, `BatchPolymerMolGraph`, and the featurizer.  It is derived
from connected components of the molecule after R-group removal, so it is robust at
`fracA = 0.5` — the case where `atom_weights` alone cannot distinguish the two monomers.

## 5. Predictions, written before the result

Primary quantity: **ΔR² on `all` rows**, reported per fold on the A split (`monomer_heldout`).

Materiality threshold, defined before running:

| Comparator | threshold | source | cells |
| --- | --- | --- | --- |
| HPG-hier (our config) | **0.069** | median per-cell across-seed SD of `delta_r2` for `hpg_hier` on `all` rows (`_regen_v1_results_individual_runs.csv`) | 18 |
| wD-MPNN (our config) | **0.052** | median per-cell across-seed SD of `delta_r2` for `wdmpnn` on `all` rows (`_regen_v1_results_individual_runs.csv`) | 18 |
| wD-MPNN (published) | **0.050** | median per-cell across-seed SD of `delta_r2` for `wdmpnn_original` on `all` rows (`_wdmpnn_original_results_individual_runs.csv`) | 18 |

The primary threshold used for the M1(ours) ↔ HPG-hier comparison is **0.069**.  The bridge
M1(published) ↔ wD-MPNN(published) uses **0.050**.  The M1(ours) ↔ wD-MPNN comparison carries
a configuration difference and is interpreted only through the bridge.

| outcome | reading |
| --- | --- |
| **M1 ≈ HPG-hier** | the monomer-level representation did it; where inter-monomer information flows is secondary |
| **M1 ≈ wD-MPNN** | having the representation is not enough; the level at which information flows is what matters |
| **M1 midway** | both contribute; report the split, do not attribute to one |

"≈" means the median per-fold ΔR² difference falls within the relevant materiality threshold
around the comparator.  Materially outside the threshold in either direction is treated as a
discriminating result.

## 6. Configuration difference

M1(ours) runs at our standard configuration (batch 64, 100 epochs, patience 15), while the
wD-MPNN reference runs at its published configuration (batch 50, 30 epochs, patience 30).
Therefore the M1(ours) ↔ wD-MPNN comparison is confounded by configuration.  The bridge run
M1(published) removes this confound; M1(ours) ↔ M1(published) isolates configuration with
architecture held fixed.

## 7. Negative controls

1. **Parameter-count check.** M1 must differ from wD-MPNN by exactly the number of parameters
   introduced by the new aggregation.  `MonomerLevelStoichAggregation` introduces no
   learnable parameters, so the counts must be identical.
2. **Monomer-index check.** On a `fracA = 0.5` polymer, the two monomers must receive distinct
   indices and the atom counts per monomer must match the SMILES fragments.
3. **Gradient-flow check.** Non-zero gradient on the aggregation output with respect to atoms
   of each monomer.
4. **Forward-pass sanity.** M1 and wD-MPNN outputs on the same batch must differ; if they are
   identical the aggregation is not being used.
5. **Path-collision check.** Output paths use the tokens `__m1` and `__m1pub` under
   `predictions/m1/`; no file may overwrite an existing wD-MPNN or HPG-hier prediction.
6. **Cap check.** No run may have `best_epoch` at the epoch cap.
